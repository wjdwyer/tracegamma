# Contributing

Issues and pull requests are welcome.

## Reporting a problem

Open an issue. For anything numerical, please include the eigenvalues or
cumulants, the function called, what you got and what you expected. A failing
example is worth more than a description.

## The rule that matters here

**Every numeric claim is checked against something independent.** This package
exists because the research code behind it had three defects that a careful
reader would not have found by reading — they were found by measuring against
an oracle. So:

- new behaviour arrives with a test that fails without it;
- any claim about accuracy is stated as a measured number against a known-exact
  reference, not as an adjective;
- if a check passes, show it can fail. A test that cannot fail is not a test.

The exact-inversion accuracy table in `python/src/tracegamma/exact.py` is pinned
by a test that also asserts the old method is *still* inaccurate at small
spectra. If that assertion ever fails, the table is stale and the test says so.

## Keeping the two implementations together

`parity.json` is generated by the Python package and consumed by the R test
suite. If you change numerical behaviour in Python, regenerate the fixture and
run the R tests; if you change it in R only, the parity test will fail, which
is the point.

## Running the tests

```
cd python && pytest --doctest-modules src/tracegamma tests
R CMD check r/tracegamma
python3 check_r_package.py r/tracegamma    # structure only, no R needed
```

## AI assistance

If you used a generative tool for a contribution, say so in the pull request:
which tool, where, and confirm you reviewed and validated the output. See
`AI_DISCLOSURE.md` for the form this project uses.
